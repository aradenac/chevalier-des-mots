# Besoins parties prenantes

Cette page résume pourquoi le projet existe.

## Enfant joueur

`req~stakeholder.child-friendly-language~1`

L'enfant doit pouvoir jouer vite, comprendre la règle en une lecture et corriger ses erreurs sans être bloqué.

Needs: dsn, utest, doc

## Parent ou enseignant

`req~stakeholder.learner-facing-summary~1`

Le parent ou l'enseignant doit pouvoir identifier le niveau, le thème et la progression pédagogique sans lire le code.

Needs: dsn, utest, doc

## Mainteneur

`req~stakeholder.maintainer-navigation~1`

Le mainteneur doit pouvoir retrouver :

- la logique du jeu;
- les règles de niveau;
- la stratégie de test;
- la procédure de build;
- la traçabilité.

Needs: dsn, utest, doc

## Mainteneur LLM

`req~stakeholder.llm-navigation~1`

Le mainteneur LLM doit disposer d'un chemin clair entre :

- objectif;
- exigence;
- architecture;
- code;
- test;
- documentation.

Needs: dsn, utest, doc

## Critères d'acceptation

- les besoins sont formulés sans ambiguïté;
- le vocabulaire reste simple;
- chaque besoin pointe vers une exigence plus précise.
